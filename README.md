# lil download

Вставляешь ссылку — получаешь файл. Настольное приложение поверх
[yt-dlp](https://github.com/yt-dlp/yt-dlp) и [ffmpeg](https://ffmpeg.org):
YouTube, Twitter/X, Vimeo и ещё тысяча сайтов, которые знает yt-dlp.

Третье в наборе — рядом с [lil edit](https://github.com/mitya-lsnk/lil-edit) и
[lil view](https://github.com/mitya-lsnk/lil-view).

## Что умеет

- **Четыре пресета и свои сверху.** «Лучшее качество» не значит «откроется
  везде»: YouTube отдаёт 4K в VP9 и AV1, а монтажки и QuickTime их не берут.
  Поэтому контейнер и кодеки выбираются отдельно от качества, а карточка
  предупреждает заранее, а не после часа скачивания.
- **Папка с памятью.** Правило на домен помнит папку, пресет и шаблон имени, так
  что твиты ложатся в одно место, а ролики с YouTube — в другое, без
  перещёлкивания между проектами.
- **Имя файла из кусочков.** Восемьдесят полей yt-dlp, которые можно таскать
  мышью, с предпросмотром и проверкой на то, что расширение стоит последним.
- **Плейлист отрезается от ссылки** по умолчанию — случайно скачать 92 видео
  нельзя, для этого есть отдельная кнопка.
- **Куки из браузера** (Firefox, Safari, Chrome, Brave, Edge, Opera, Vivaldi,
  Chromium). Сами куки через приложение не проходят — yt-dlp читает их сам, мы
  передаём только название браузера.
- Обрезка по времени, субтитры файлом или в контейнер, SponsorBlock,
  ограничение скорости, свои флаги yt-dlp с подсказками.

## Установка

Готовые сборки — во [вкладке Releases](../../releases). На macOS приложение не
нотаризовано: первый запуск — правой кнопкой → «Открыть».

yt-dlp и ffmpeg приложение ставит себе само, рядом с собой. Внутрь они не
вшиты намеренно: yt-dlp обновляется каждые пару недель вслед за YouTube, а
ffmpeg распространяется под GPL.

## Сборка из исходников

```bash
npm install
npm run tauri dev     # разработка
npm run tauri build   # сборка под текущую систему
```

Нужны Node 22+ и Rust. Сборки под все четыре платформы делает
[CI](.github/workflows/build.yml) — локально кросс-компиляция под Windows
требует MSVC SDK, LLVM и NSIS, и оно того не стоит.
