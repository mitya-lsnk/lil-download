## 2. Экраны

**Главный — одно поле.** Как `home-drop` в lil edit: большая зона, куда
вставляешь ссылку (или дропаешь текст/файл со ссылками). При фокусе окна
подсматриваем буфер обмена: если там URL — предлагаем «Вставить `⧉`» одной кнопкой.

**Карточка ссылки.** До скачивания дёргаем `yt-dlp -J` → показываем обложку,
название, канал, длительность, доступные форматы. Пользователь видит, что
именно он качает, до того как оно поехало. Здесь же — пресет и папка (§4).

**Пресеты** — крупные карточки как `HomeScreen` в lil edit (01/02/03 + цветной
класс), не выпадающий список.

**Очередь.** Список задач: прогресс, скорость, ETA, пауза/стоп/повтор,
`⎘` показать в папке. Параллельность ограничена (по умолчанию 2).

**Настройки.** Папка по умолчанию и правила по источникам, шаблон имени файла,
лимит скорости, лимит параллельных, пути к yt-dlp/ffmpeg + их версии и кнопка
«Обновить», прокси, куки (§7), скин/язык/тема.

## 3. Пресеты

Дефолт — **Максимум**. Названия нейтральные:

| Пресет | Что делает |
|---|---|
| **Максимум** ← дефолт | `bv*+ba` как есть, ремукс в mkv/mp4, ничего не режем и не перекодируем |
| **Совместимый** | H.264 ≤1080p + AAC в mp4: `bv*[vcodec^=avc1][height<=1080]+ba[ext=m4a]/b[ext=mp4]` — открывается везде без плясок |
| **ProRes** | качаем лучшее и перегоняем ffmpeg'ом в ProRes 422 LT + PCM в .mov |
| **Только звук** | m4a / mp3 320 / wav |
| **Компактный** | 720p mp4, мелкий, быстрый — посмотреть и выкинуть |
| **Свой** | ручной выбор формата из списка, что вернул `-J` |

- [ ] Пресеты — данные, а не код: JSON-описание (селектор формата + ffmpeg-аргументы),
      чтобы можно было добавлять свои и делиться ими.
- [ ] **Пометка о совместимости.** Раз дефолт «Максимум», ютубовские 4K приедут в
      VP9 или AV1 внутри webm, а Resolve на маке их не жуёт — либо не открывает,
      либо картинка без звука. Поэтому: если выбранный формат из этого списка,
      в карточке показываем спокойную строчку «монтажки могут не открыть» и
      кнопку «Взять совместимый». Не навязываем, просто не даём вляпаться молча.

## 4. Куда сохраняем

По умолчанию `~/Downloads`. В карточке ссылки — строка папки `⌂` и две галочки:

- [ ] **Запомнить эту папку** — станет папкой по умолчанию для всего дальнейшего
- [ ] **Запомнить для этого источника** — правило «x.com → сюда»

Приоритет при подстановке: **правило источника → последняя папка → `~/Downloads`**.
Смысл в том, чтобы твиттер валился в одно место, а ютуб в другое, и между
проектами руками ничего не переключать.

- [ ] Правило вешается **на домен** (решено 25.08), живёт в настройках отдельным
      списком: `youtube.com → ~/Footages/YT`, редактируется и удаляется.
- [x] Правило запоминает не только папку, но и **маску** *(решено 25.08: всё)* — пресет, шаблон имени и
      ffmpeg-галочки, с которыми качали с этого источника. Вставил ссылку с x.com —
      подставились папка, пресет и имя, которые ты там в прошлый раз выбрал.
- [ ] **Нормализация домена — обязательно, иначе правила расползутся.**
      `x.com` и `twitter.com` — один источник; `youtu.be`, `m.youtube.com`,
      `www.youtube.com` — тоже один. Список синонимов держим явным, не гадаем.
- [ ] В карточке подписываем, откуда взялась папка («правило x.com»), чтобы
      файл не уехал в неожиданное место молча.
- [ ] Конфликт имён: не перезаписываем — дописываем ` (2)`.

**Плейлист в ссылке — отрезаем.** Копируешь ролик из плейлиста, а качается вся
сотня — это самый бесячий дефолт yt-dlp, и он выключается. Делаем две вещи сразу,
потому что каждой по отдельности мало:
- [ ] Всегда передаём `--no-playlist` — это то, что реально останавливает yt-dlp.
- [ ] Плюс чистим сам URL от плейлистного хвоста (`list=`, `index=`, `start_radio=`,
      `pp=`) — чтобы и в карточке, и в истории лежала честная ссылка на одно видео.
- [x] `t=` (метку времени) **не выкидываем**: подставляем в поле «начало обрезки»
      в §7, но саму обрезку оставляем **выключенной**. Таймкод замечен, качается всё
      видео, включить — один клик. *(решено 25.08)*
- [x] Если плейлист всё-таки был — маленькая плашка «в ссылке был плейлист,
      92 видео → скачать целиком?». Не модалка, не вопрос, просто есть. *(решено 25.08)*

## 5. Имя файла — конструктор

Не поле с `%(title)s` для тех, кто помнит синтаксис. Собираем имя из **чипов**,
которые можно таскать мышью, менять местами и удалять, между ними — свой текст.

- [ ] Палитра готовых тегов, которые знает yt-dlp: название, автор/канал,
      дата загрузки, источник, id, разрешение, fps, кодек, длительность,
      расширение, номер в плейлисте. Клик — добавить, drag — переставить.
- [ ] Поиск по палитре: тегов у yt-dlp много, всё в один экран не влезет.
- [ ] **Живой превью** прямо под конструктором, на метаданных настоящей ссылки
      из карточки, а не на «Example Video» — сразу видно, что получится.
- [ ] Сырой режим: переключатель в текстовое поле с шаблоном, для тех случаев,
      когда чипов не хватает. Туда-обратно без потерь.
- [ ] Пара заготовок из коробки: `Название`, `Дата — Канал — Название`,
      `Канал / Название [1080p]`.
- [ ] Санитайзинг обязателен и кроссплатформенный: винда не переваривает
      `< > : " / \ | ? *`, у всех лимит ~255 байт на имя, эмодзи в названиях
      роликов ломают часть монтажек. Режем аккуратно и показываем в превью
      уже почищенное.
- [ ] Шаблон запоминается в маске источника (§4).

**VK**, **SoundCloud**, **Coub**, прямые ссылки на mp4/m3u8.

## 8. Куки (фаза 4, как и договорились — после того как хоть что-то качает)

Больное место yt-dlp, и ты прав про Firefox:
- **Firefox** — читается чисто на всех системах, ничего не просит.
- **Chrome/Brave/Edge на macOS** — база кук зашифрована ключом из Keychain;
  yt-dlp умеет, но система покажет запрос доступа к связке ключей.
- **Chrome на Windows** — DPAPI, работает без вопросов, но только под тем же
  пользователем Windows.
- **Safari** — файл кук читается только с Full Disk Access у приложения.

План: выбор браузера + профиля в настройках, честное объяснение, что именно
система спросит и почему, кнопка «Проверить» (дёргаем приватное видео и
показываем результат), плюс запасной вариант — импорт `cookies.txt`.

- [ ] Ни в коем случае не парсить куки самим и никуда их не отправлять —
      только передавать yt-dlp `--cookies-from-browser` / `--cookies`.

## 12. Что подсмотрели у Stacher7

Референс, который дал пользователь — самый развитый GUI над yt-dlp. Взяли не
всё: половина его возможностей тянет приложение в сторону медиатеки, а у нас
принцип «одно дело — хорошо» и для просмотра уже есть `lil view`.

**Берём:**
- [ ] **Именованные конфигурации с быстрым переключением.** У нас маска
      привязана к домену и создаётся молча. Ход Stacher лучше сочетается:
      пресет — именованная штука, которую можно выбрать вручную, а правило
      источника просто указывает на неё. Один объект вместо двух.
- [ ] **Поиск по настройкам.** У Stacher это Spotlight: печатаешь «субтитры» —
      попадаешь в нужный раздел. У нас уже запланирован поиск по тегам в
      конструкторе имени (§5); тот же механизм стоит распространить на все
      настройки, их будет много.
- [ ] **Очередь: параллельно или строго по одной.** У нас только лимит
      параллельных задач. Явный режим «по очереди» стоит две строки и нужен
      на слабом канале.
- [ ] **SponsorBlock в пост-обработке.** Вырезать спонсорские вставки — ровно
      то, что нужно монтажёру, и yt-dlp умеет сам (`--sponsorblock-remove`).
      Кладём в §7 к остальным ffmpeg-правкам.
- [ ] **Экспорт/импорт конфигураций.** Дёшево, раз пресеты и так JSON (§3).

**Сознательно не берём:**
- **Медиатека с тегами, заметками и категориями.** Это отдельное приложение.
- **Встроенный плеер** с главами и превью. Для этого в наборе есть `lil view`,
  а видео должен открывать системный плеер — дублировать не будем.
- **Подписки на каналы** с автоскачиванием. Превращает загрузчик в качалку,
  которая живёт в фоне и ест диск. Если и делать, то сильно потом и отдельно.
